# fotoframe アーキテクチャ

仕様は [spec.md](spec.md) を参照。

## 表示環境

Raspberry Pi OS Desktop 版の自動ログインと labwc（Wayland コンポジタ）はそのまま使い、labwc の autostart ではパネルやファイルマネージャなどを起動せず、本アプリだけを起動する。

- デスクトップ環境の常駐プロセス（パネル、ファイルマネージャ等）を止めることで、メモリ使用量を約 200MB 減らせる
- 消灯（F9）は `wlopm` でモニターをスタンバイにできる
- labwc の設定はユーザー設定で完結し、sudo は不要

検討した他の案：

- デスクトップ環境をそのまま使う：常駐プロセスのメモリが無駄になる
- デスクトップなしで KMS/DRM に直接描画する：最も軽いが、消灯のための DPMS 操作を自前で実装する必要があり、手間が大きい

## アプリ

C++ で実装する（学習目的も兼ねる）。

| 項目 | 採用 | 理由 |
|---|---|---|
| 描画 | SDL3 | GPU レンダラで Wayland 上にフルスクリーン表示できる。SDL2 は保守段階のため新しい SDL3 を使う |
| JPEG デコード | libturbojpeg | 高速。デコード時に 1/2、1/4 などへの縮小ができ、大きな写真でも FHD 相当に縮小しながら読み込める |
| EXIF 回転情報 | libexif | Orientation を読み取って回転させる |
| JPEG 以外の形式 | 対応しない | 表示対象は JPEG のみ。サンプルの写真はすべて JPEG だった |
| ビルド | CMake | |
| 言語規格 | C++20 | |
| 並行処理 | `std::thread` | 画像の読み込み・デコードとフォルダ走査をバックグラウンドで行い、描画を止めない |

切り替え効果は GPU 上のテクスチャの透明度・位置の変更で描画する。

検討した他の案：

- ブラウザ（Chromium キオスクモード）＋HTML/JS：実装は容易だが、メモリ使用量が一桁多く、24時間稼働での安定性に不安がある
- Python＋pygame：実装は最も容易。メモリ差は小さいが、学習目的で C++ を選んだ

## システム設定

- スワップ：zram のみ（`/etc/rpi/swap.conf.d/` で `Mechanism=zram`）。OverlayFS 使用時は microSD 上のファイルへの書き戻しが役に立たないため
- NAS：OS 側で CIFS としてマウントする。アプリはマウント先のフォルダを読むだけ
